Sunghyun Sans sources are drawn SHARP. Rounding happens at export via per-instance custom parameter filters: "RoundCorner; R; 1" with R from 45 (Thin) to 165 (Black); the CJK packages carry a second filter "RoundCorner; 70; 1; include: name=*-ko" so Korean glyphs round at a fixed radius. The filter rounds every closed path and every component outline INDEPENDENTLY, before overlaps merge. Per-shape rounding is the intended house style for the stroke-built glyphs (Hangul and most Latin junctions are crossings or T-joints whose union corners are concave, which the filter leaves sharp, so they render identically to merged outlines).

**Why:** Glyphs runs Filter custom parameters before overlap removal, so a glyph built from a piece whose edge should continue another stroke flush (the arm of ъ) gets two independently rounded corners and the union keeps a crease (GitHub issue #5, fixed 2026-07-23).

**How to apply:**
- The fix is a scoped "RemoveOverlap; include: <86 glyph names>" filter inserted BEFORE RoundCorner in each of the 9 static instances of all 5 packages. Merge-then-round reproduces SF Pro Rounded's continuous junctions for exactly those glyphs and leaves every other glyph bit-identical (verified by FreeType 64ppem bit-exact comparison across the full cmap of all weights).
- Of the 91 encoded characters in the merge list, only 47 actually render differently (identical sets at 64 and 256 ppem). The rest have crossing-type junctions: the union's corners coincide with each piece's own convex corners, so merged-then-rounded is geometrically identical to rounding each piece alone. Merging them is a harmless no-op that guards future edits; a release's affected-character list must come from the rasterized regression run, not from the include list.
- Do NOT fix by removing overlap in the sources: 8 of the affected glyphs (ae, babygamma, ccurl, Cheabkhasiancyrillic, interrobang, eurocurrency, peseta, lbelt.ss02) merge to different topologies per master and become interpolation-incompatible ("no outlines" in heavy weights), even after Correct Path Direction (All Masters).
- Do NOT add merge filters to the `type = variable` settings: per the Glyphs handbook (handbook.glyphsapp.com/filters/applying), merge filters on variable exports can produce incompatible outlines; the shipped pipeline builds static instances only.
- A same-day re-export of unmodified sources is bit-identical to shipped binaries, so pixel-compare against the previous release is a valid regression gate; grid-rounding jitter of 1-2 units appears only on glyphs whose node structure changes.
- The RemoveOverlap FILTER only merges shapes with real area overlap: zero-overlap abutments (edges exactly touching) stay separate and each piece gets rounded alone, which detaches it visually (a 1-2 unit gap plus capsule ends). hardsigncyrillic, ljecyrillic, and lrthook had such abutments in some masters and were fixed by extending the abutting element into its neighbor (32 to 42 units, to fixed target coordinates) in every master that lacked positive overlap, in all packages. When adding glyphs to the merge list, verify each junction has positive overlap in ALL masters, and after export run the abutment scan (contour pairs with a 0-6 unit gap) over the binaries: a passing pixel-compare allowlist does NOT prove the change was correct, only that it was scoped.
- The Glyphs UI Path > Remove Overlap on font-view selections does NOT decompose components, so it cannot merge a path with a component either; do not rely on it for this class of fix.
- update-fonts.sh syncs from Glyphs' Temp folder by filename count; a sync started while Glyphs is still writing can ship a truncated file. Wait for Temp file sizes to be stable across two checks before syncing, and size-audit fonts/ against Temp afterward (a 0-byte Disambiguated-Black.ttf shipped transiently this way on 2026-07-23 and was caught by the audit).
- Adding glyphs to the fix list later: append the glyph name to all 45 RemoveOverlap include lists (and the component-reference closure of that glyph: CFF decomposes composites into own-named copies that must be listed themselves, while TTF inherits through components), re-export, and pixel-compare with the new name in the allowlist.
